S/W Week8 · 2

지난주 이후 구현한 것을 한 장에 모았습니다. 백엔드는 통증 기록 API 4개에서 23개가 되었고, 질환과 아침 체크인을 넣을 수 있게 되어 판정이 끝까지 동작합니다. 그리고 이걸 직접 보여 드리려고 브라우저에서 돌아가는 데모 앱을 만들었습니다. 데모에는 통증 점수를 고르기 쉽게 돕는 화면, 운동 추천 페이지, 의학 정보와 OX 퀴즈가 들어 있습니다. 바로 화면으로 보여 드리겠습니다.

S/W Week8 · 3

만든 API를 기능별로 정리했습니다. 지난주에는 통증 기록 4개만 있었고, 이번 주에 나머지 여섯 개 파일, 19개를 새로 만들어 모두 23개입니다. 기능마다 파일을 하나씩 두었고, 표에는 대표 API를 하나씩만 적었습니다. 예를 들어 질환은 화면에서 체크한 목록을 통째로 보내 바꾸고, 아침 체크인은 하루에 한 번만 있어서 다시 보내면 고치도록 했습니다. 실제로 어떻게 쓰이는지는 바로 시연으로 보여 드리겠습니다.

S/W Week8 · 4

이제 화면으로 보여 드리겠습니다. 시연 상태로 시작한 뒤, 통증을 기록하고, 판정 결과와 운동 추천을 보고, 의학 정보 퀴즈를 풀어 보겠습니다. 마지막으로 화면 아래 API 기록을 열어, 버튼을 누를 때마다 실제 서버와 같은 주소로 요청이 가는 것을 보여 드리겠습니다.

만들면서 막혔던 곳

어려웠던 점

DB

코드를 짜다가 DB 설계의 빈틈 발견

활동 기록 번호에 AUTO_INCREMENT · 외래키가 없었음 → 마이그레이션 003 파일로 고쳐서 어디서든 같은 순서로 적용

TIME

'오늘'은 어디서 자르나

DB는 UTC라 한국 아침 기록이 전날로 묶임 → 사용자 시간대로 바꾼 뒤 날짜별로 묶음

GRAPH

하루 2번 기록하면 그래프엔 몇 점?

평균이면 9점이 묻히고, 최고면 하루 종일 아픈 것처럼 보임 → API가 횟수 · 평균 · 최고 · 마지막을 모두 주고 화면이 고름

S/W Week8 · 5

만들면서 어려웠던 점은 세 가지입니다. 첫째, 저장 코드를 짜다가 ERD에서 몰랐던 빈틈을 발견해서 마이그레이션 파일로 고쳤습니다. 둘째, DB 시각이 UTC라서 한국 아침 기록이 전날로 묶이는 문제가 있어, 사용자 시간대로 바꾼 뒤 날짜를 나눴습니다. 셋째, 하루에 통증을 두 번 기록하면 그래프에 무엇을 찍을지 고민했고, API에서는 평균, 최고, 마지막 값을 모두 내려주도록 했습니다.
